# purge v0.8 — robustness, trash mode, coverage, and the star loop

**Status:** approved in chat, building directly
**Date:** 2026-09-12
**Origin:** 1.2k npm downloads, 1 GitHub star. Launch-day spike, no
retention. The code is sound; the funnel and a handful of trust gaps are not.

## 1. Problem

Three things stop a happy user from becoming a star, a recommender, or a
contributor:

1. Nothing in the tool ever points a user at GitHub — the moment
   `reclaimed: 23 GB` prints is the only moment anyone would star, and the
   tool says nothing.
2. "There is no undo" is the sentence that stops a deletion tool from being
   recommended to a colleague.
3. Several failure modes are silent or misleading: a path that fails to
   delete is reported as "changed since the scan"; Ctrl+C mid-deletion
   leaves no manifest; long rows garble the review screen on an 80-column
   terminal.

Coverage gaps found reading the scanners: Electron app caches (Slack,
Discord, Notion, Figma, ...), Go/Maven/CocoaPods/pub/conda/NuGet/Composer
caches, Terraform and Flutter/Android/CMake/Maven build output, and heavy
items (simulator devices, Android system images and AVDs, Ollama and
LM Studio models, OrbStack data).

## 2. Design

### 2.1 Tier 1 — robustness and the star loop

- **Star line.** `renderSummary` takes `runCount`; when `runCount <= 3` it
  appends one dim line pointing at the repo. TTY only (color on), never in
  `--json`, never when nothing was freed. `runCount` is the number of
  manifests in `~/.purge/runs` after this run's manifest is written — no new
  state, no network.
- **Failure reporting.** `RunManifest` gains `failed: Array<{path, bytes,
  group, reason}>`. The reaper records `err.code` (EACCES, EPERM, EBUSY,
  ENOTEMPTY, ...) instead of swallowing it. cli.ts prints each failed path
  with its reason, separately from guard-skipped items.
- **Interrupt safety.** `reap` accepts `signal?: AbortSignal`. When the
  signal fires the loop stops before the next item; what was already
  removed is still written to the manifest. cli.ts wires SIGINT to an
  AbortController during the reap phase and prints the partial summary.
- **Manifest write failure is not fatal.** `reap` catches `writeManifest`
  errors and returns the manifest with `manifestPath: null`; cli.ts prints
  the summary and a one-line warning that the record could not be saved.
- **Row truncation.** `renderFrame` takes `width`. A row longer than `width`
  has its path middle-ellipsized (`~/Library/App…/Slack/Cache`) so that
  checkbox, size, path tail, note and warning all fit on one line. Pure
  helper `fitRow` in tui-state.ts, tested.
- **Node version notice.** If `process.versions.node` major is below 22,
  print one stderr line naming the tested minimum and continue. The bundle
  parses on older Node, so a hard block would only hurt.

### 2.2 Tier 2 — trash mode and undo

- `--trash` flag and `"trash": true` in `~/.purgerc`. `Options.trash`.
- In trash mode the reaper `fs.rename`s each item into `~/.Trash/<basename>`
  (suffixing ` (purge N)` on collision) instead of `fs.rm`. Home and the
  Trash are on the same volume by construction (the volume guard blocks
  anything else), so the rename is instant and keeps allocated sizes.
- The `.Trash` heavy row itself always uses `fs.rm` — it cannot be moved
  into itself.
- `ReapedItem` gains `trashedTo?: string`; `RunManifest` gains
  `mode: 'rm' | 'trash'` (absent = `'rm'` for old manifests).
- `purge undo` reads the newest manifest with `mode === 'trash'` and renames
  every `trashedTo` back to `path`, skipping any whose original path exists
  again or whose trash copy is gone. Restore targets must be under home and
  sources under `~/.Trash`; anything else is refused. Lives in
  `src/reap/undo.ts`; does not call `fs.rm`, so the reaper invariant holds.
- Summary wording changes in trash mode: `moved to Trash: 23 GB` plus a hint
  that emptying the Trash frees it and `purge undo` restores it.
- `purge history` shows a `trash` marker on trash-mode runs.

### 2.3 Tier 3 — coverage

- `electron.ts` (PathScanner, group `caches`): for every directory under
  `~/Library/Application Support` that contains BOTH `Cache` and
  `Code Cache` (the Chromium profile signature), claim `Cache`, `Code Cache`,
  `GPUCache`, `DawnGraphiteCache`, `DawnWebGPUCache` when present. Never
  `Service Worker`, `Local Storage`, `IndexedDB`, `Session Storage`. Skips
  app dirs owned by the editors, agents and browsers scanners, and any path
  already in `claimed`.
- `pkg-cache.ts` additions: `go/pkg/mod/cache`, `.m2/repository`,
  `.cocoapods/repos`, `.pub-cache`, `.nuget/packages`, `.composer/cache`,
  `.yarn/berry/cache`, conda `pkgs` under `miniconda3`, `anaconda3`,
  `miniforge3`, `mambaforge`, `.conda`.
- `builds.ts`: UNAMBIGUOUS gains `.terraform`, `.dart_tool`, `.gradle`,
  `.serverless`, `.tox`, `.mypy_cache`, `.pytest_cache`, `.ruff_cache`,
  `.angular`, `.docusaurus`. AMBIGUOUS becomes a per-name manifest map:
  `dist`/`build` next to JS manifests, `pubspec.yaml`, `build.gradle(.kts)`,
  `settings.gradle(.kts)`, `CMakeLists.txt`; `target` next to `pom.xml` or
  `build.sbt`; `.cache` next to `package.json`.
- `xcode.ts`: adds `Library/Developer/Xcode/UserData/Previews` (SwiftUI
  preview simulators, regenerable).
- `heavy.ts` additions, all dangerous via `danger.ts`: simulator devices
  (`Library/Developer/CoreSimulator/Devices`), Android AVDs (`.android/avd`)
  and system images (`Library/Android/sdk/system-images`), Ollama models
  (`.ollama/models`), LM Studio models (`.lmstudio/models`,
  `.cache/lm-studio/models`), OrbStack data (`.orbstack/data`). `danger.ts`
  becomes a label → warning table.

### 2.4 Outside the code

- GitHub: description, homepage, topics; social preview image generated
  under `docs/social-preview.png` for upload.
- `release.yml`: `contents: write`; a step creating a GitHub Release whose
  body is the matching CHANGELOG section; a best-effort job that bumps the
  Homebrew formula when `TAP_GITHUB_TOKEN` is set.
- Homebrew tap repo `soummyaanon/homebrew-tap` with `Formula/purge.rb`
  (`depends_on "node"`, npm tarball URL + sha256).
- README reordered: GIF and install first, troubleshooting last, a
  comparison table, `--trash` and `undo` documented.
- Seed issues for Linux support and remaining coverage ideas.

## 3. Invariants kept

- Only `src/reap/reaper.ts` calls `fs.rm`. `undo.ts` renames only.
- Zero runtime dependencies.
- Sizes from allocated blocks.
- Every behaviour change starts with a failing test.
